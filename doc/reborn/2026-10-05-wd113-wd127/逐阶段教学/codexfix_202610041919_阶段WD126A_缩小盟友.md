# WD126A：为什么缩小盟友用原生光环

先从官方职业节点 30888 找到 Spell 806282，而不是凭天赋名称猜技能编号。DBC 的三个效果槽里，第 1 槽是闪避光环、第 2 槽是 Dummy、第 3 槽是模型缩放光环；BasePoints 在客户端采用“值减一”表示法，所以 49 显示为 50%，-26 对应约 -25%。持续时间引用 SpellDuration 31，即 8000 毫秒；RecoveryTime 是 120000 毫秒。

本项目原本的药水投掷是友方技能，可当作安全的私有法术模板。复制其通用施法框架后，仅把官方三个效果槽、目标、光环、时长、冷却和图标写入新 ID 9003910；把等级设为 10，法力百分比设为官方 15。服务端和客户端各自从自己的 Spell.dbc 追加，不能把某一端的整张表复制给另一端。

天赋节点、C++ mask、Lua mask 和 Characters 存储过程同时加第 98 位。若只改客户端，点击能亮但服务端不会保存；只改数据库，则重登后 C++ 会把方案判为未知位。保存方案激活时学习技能，切走时移除。World SQL 只把一个校验脚本绑定到新技能，闪避与缩放仍由核心原生光环处理，避免重复计算。

最后对旧 DBC 每条记录逐字比对，确认新私有 ID 不覆盖已有技能；再在隔离 MySQL 执行实际存档过程，验证合法保存、非法前置、错误专精和已保存点不能免费撤销。离线检查能确认数据链自洽，不能替代用户在客户端确认图标、动作条冷却与战斗闪避。
