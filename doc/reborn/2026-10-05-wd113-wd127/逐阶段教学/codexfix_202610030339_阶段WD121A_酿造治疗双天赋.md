# 从配料天赋理解完整移植

把三个层次想成菜单、厨房和账本：Lua负责展示菜单；C++和DBC决定厨房实际怎么做；Characters SQL保存你买了哪份菜单。只点亮图标会出现“看着学会、实际没加成”，只写效果又会出现“重登丢失”。本批必须三层一致。

## 第一步：不要用关闭状态代替证据

新鲜配料Issue1142关闭了，但合并审计明确没有证明数值生效。官方20260925的说明写“大锅蘑菇”，因此追到WD120的大锅隐藏治疗9003866；投掷附带的9003867是另一个法术。英文名相同不代表目标相同。来源和完整字段见来源与适配说明及research。

## 第二步：给每个增益准确地址

交付的RebornWitchDoctor.cpp中新增：

```cpp
if(mod->spellId==9003877 || mod->spellId==9003878)
    return check->Id!=9003866 || mod->op!=SPELLMOD_DAMAGE;
if(mod->spellId==9003879)
    return !((check->Id>=9003870 && check->Id<=9003876 && mod->op==SPELLMOD_DAMAGE) ||
             (check->Id==9003867 && mod->op==SPELLMOD_DOT));
```

第一行识别新鲜配料的两个等级；第二行只匹配大锅脉冲和op0。这个历史接口约定返回false表示“明确匹配”，与普通布尔命名直觉相反，必须结合SpellInfo.cpp的调用读。第三行识别药水增效；第四行匹配七个直接投掷等级；第五行匹配投掷后的持续治疗。`||`表示满足任意一条，`&&`表示同时满足。SPELLMOD_DAMAGE名称虽然写damage，原生治疗函数也用它处理直接治疗；DOT对应周期治疗。

SpellInfo.cpp同时把9003877/78/79加入精确匹配保护列表：上面未命中时立即拒绝，不进入空family mask的广泛匹配。这是负向测试的核心，不能只看自己的治疗有没有提高。

## 第三步：数值只乘一次

Spell.dbc效果71设6（施加光环），95设108（百分比法术修正），110为操作号；80存14或29或19，因为这里DieSides=1，实际数值为15/30/20。药水增效第二效果在72/96/111/81中分别存6/108/22/19。名称和描述的16个语言偏移各自指向本端新字符串，不能直接搬官方偏移。

假设同条件下某次大锅治疗为1000，一级新鲜配料应为1150，二级1300，不能变成1450；原始投掷1000，药水增效后1200。两个天赋覆盖不同法术，所以不是1300再乘1.2。随机范围、舍入、暴击、目标增益和过量治疗会影响实机观察，必须固定条件、比较多次非暴击样本。

WD120先把等级基础量、治疗系数、精神加成组合，再交给原生SpellHealingBonusDone。本批在那里处理百分比；绿色Tooltip也走这个函数，不再在Lua手工乘一次。

## 第四步：存档位不搬家

```cpp
if(index==77) return static_cast<uint32>((mask>>87)&3u);
if(index>=78) return static_cast<uint32>((mask>>(index+11))&1u);
```

第一行从87位开始读两位，能表示0/1/2/3，但验证拒绝3；第二行让index78落在89位。原有技能位不动，才不会把旧技能读成新技能。Lua用四段32位整数和十进制字符串传输，SQL用DECIMAL和整数权值；不能把90位数塞进Lua浮点number。

```sql
SET r77=MOD(FLOOR(p_mask/154742504910672534362390528),4);
SET r78=MOD(FLOOR(p_mask/618970019642690137449562112),2);
```

两个除数分别是2的87次方和89次方。FLOOR去掉小数，MOD4取两位，MOD2取一位。SQL还检查同层不凑基础8TE、分支正确、点数足够、旧点不得免费减少。重复安装只更新规则，不清空购买和方案记录。

## 第五步：学习和撤销成对

AEApply用`fresh==1`、`fresh==2`决定唯一等级，先删除另一等级技能和自身Aura，然后学习需要的等级。即使技能已学习但Aura缺失，仍会补CastSpell。换出方案则移除被动；友方身上已落下的HoT按原生快照持续到结束，新效果通过重新投掷更新。

## 第六步：分清测试能证明什么

tools/scenario121.lua验证加点、最高等级、精确90位、预算和跨专精拒绝。tools/test_mysql.py启动隔离临时MySQL，先验证@@datadir，再测试旧/新角色数据、重复导入、回退守卫，finally关闭；它不会连接生产库进行写入。checks/sql_trace.jsonl记录实际SQL及返回，只包含合成测试角色。

wd121_audit_checks.py读取真正交付的DBC数值，结合原生治疗调用路径，检验720个加成及无关技能模型；它不能证明C++已编译或游戏运行成功。用户应按README矩阵检查实际治疗、保存、重登和图标。首次SQL旧用例异常没有根因，所以保留记录，不能把最后绿灯写成这个旧问题已修复。

练习：先记录没有两个被动的大锅、投掷、HoT；依次加一级、二级、药水增效，每步填入正向与负向观察，再检查换回其他方案。确认结果后才把本候选流程晋升永久已验证技能。
