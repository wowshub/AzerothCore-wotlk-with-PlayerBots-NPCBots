# WD125A 新人教学：一个“配料”为什么有四个法术

以鱼油为例，技能书只显示准备技能 9003901。玩家点它后，自己获得持续的准备光环；光环每隔约 1.5 秒触发 9003902，给 40 码内团队成员短暂的加速光环。药水投掷命中友方时附加 9003903，泼洒药水命中友方时附加 9003904。后面三个是游戏内部效果，不应当变成技能书图标。蛙骨用 9003905–9003908 完全对应的链。这样拆分，才能分别控制技能书可见性、范围增益与单次药水效果。

`Spell.dbc` 描述客户端与服务端都要认识的法术基础数据：效果类型、光环类型、持续时间、范围、图标、提示。`SkillLineAbility.dbc` 只给两个“准备技能”加书页记录，隐藏子法术没有书页记录。这正是之前假死和显性诅咒出现“已学但书里找不到”时要核查的一层。两端 DBC 从各自 WD124A 累计文件复制增量，不能拿服务端文件替换客户端文件。添加记录后检查旧行完全一致，避免一个新技能把已有技能弄坏。

`RebornWitchDoctorBrewingFoundation.inc` 中 `Snapshot()` 先记住发射药水时准备的是蘑菇、鱼油还是蛙骨。随后切换配料也不改变空中这瓶药水的效果；`IngredientEffect()` 仅对友方、存活目标施加对应附效。蛙骨的护盾量用 `100/25 + 0.35×精神 + 0.80×自然治疗加成` 算出，再作为 CastCustomSpell 的基础值传给目标。鱼油的闪避、移动及急速直接用 WotLK 核心支持的原生 Aura 值，减少重复写伤害／移动钩子。

天赋保存是另一条链：客户端 Lua 将蛙骨写进第 85 个节点，即第 97 个 bit；C++ 读取相同位置，Characters SQL 也从同一位置计算 r85。如果其中一边错一位，界面会显示已选但重登后无技能，或 SQL 无声地拒绝保存。本次隔离 MySQL 套件把“没大锅时拒绝”“保存后重读”“切错专精拒绝”“旧方案不能免费删点”“第 98 位越界”都跑了一遍。鱼油是 16 级普通技能，所以不占 bit，也不花点。

安装时先备份，再覆盖源码和两端 DBC、导入新版 Characters SQL 与新增 World SQL、重编译并重启；不要把本教学中的示例数字当作实机通过证据。若客户端只出现图标而实际无加速／护盾，先查 World 脚本绑定和服务端 DBC；若只有实际效果却没图标，先查客户端 Spell 与 SkillLineAbility；若切方案后错乱，查 C++／Lua／SQL 的节点编号和 bit 是否一致。
