# WD113A：通用巫祝、破咒与诅咒增强

接在已实测通过的 WD112A 累计包上。此次优先补齐通用技能增强；酿造配料／大锅／投掷药剂机制尚有依赖缺口，未用空节点提前开放。

| 节点 | 效果 | 加点条件 |
|---|---|---|
| 洛阿强化 6381 → 9003850 | 巫祝耗蓝降低50%；力量巫祝效果提高20% | 先投入9点基础AE，再花1 AE |
| 希里克的祝福 12048 → 9003851 | 破咒术额外尝试移除1个诅咒 | 同上；与黑暗魔精二选一 |
| 显性诅咒 11323 → 9003852 | 倦怠、希里克、法力、缩小、恶毒诅咒耗蓝降低25% | 先投入9点基础AE，再花1 AE |

三项属于通用树，巫毒、酿造、暗影狩猎绑定方案均可选择。9点基础示例：治疗守卫1、灵性传统1、睿智2、寻觅者1、净化神像1、拟态守卫1、巫毒注射2。也可以用天选之人计入基础点。新三项以及已有同层高阶节点不能反过来凑这9点。
已有黑暗魔精的方案不能直接加希里克的祝福，需按现有规则重置该方案后重新选择；其他保存方案保持不变。

## 安装
1. 停服前备份 Characters 数据库及相关源码、Lua、双端DBC、客户端 patch-XA.MPQ。
2. 将 `01_覆盖到源代码根目录` 全部覆盖到当前累计源码后编译；成功后使用新服务端程序。包含核心 SpellInfo.cpp，不能只覆盖模块。
3. 在 **Characters** 执行 `server_SQL/01_CHARACTERS_WD113A_必须执行.sql`，确认无错误。支持75位传输，存储仍是原node_id/node_rank行；不删除方案、购买记录或动作条。不要执行旧WD112 Characters SQL覆盖回来。
4. 覆盖 `02_覆盖到客户端根目录`，保留已经安装的 WD107 提示、WD108 Profiles。
5. 覆盖 `03_覆盖到服务端根目录`。将 `client_mpq输入_导入现有Patch-XA` 内容导入当前 patch-XA.MPQ 对应内部路径；客户端和服务端的同名DBC不能混用，MPQ备份移出Data。
6. 已完整安装 WD112 的用户不需要新增 World SQL；本包附带的 WD112 World SQL只是累计依赖，若未安装WD112应先按其说明完成。
7. 启动服务端、重开客户端，先检查旧方案再加点。DRBOT1A改的是两个PlayerbotAI文件，本包无这些路径，两包可叠加；机器人自动变龙仍待你测试。

## 实测顺序
1. 原巫毒、第二套酿造购买状态、加点、动作条仍在；各新节点保存、切方案、/reload、小退、大退后仍正确。空未购买槽不阻塞读取。
2. 洛阿强化：同装备、其他Buff相同，对比点前/点后的巫祝实际扣蓝。灵魂、力量、节能及对应强效巫祝都应下降50%；力量巫祝和强效力量巫祝攻击强度增益提高20%（整数可能取整）。已存在增益要重新施放；洛阿佳酿、召唤技能和普通伤害技能不应受这项减耗。
3. 希里克的祝福：给友方挂两个可驱散的不同诅咒，破咒术从一次最多尝试1个变为2个；只有1个时正常。驱散抵抗/特殊不可驱散效果仍按原生规则；不能额外解除疾病、毒或魔法。与黑暗魔精同时选择应被拒绝，单选各自正常。
4. 显性诅咒：比较上述五类技能实际耗蓝，预期为未点时75%；缩小诅咒所有等级包括在内。恶意妖术、邪恶巫术、恶意之怒、妖火、洛阿佳酿、破咒术都不应被这项减耗。
5. 切出含本批天赋的方案后，新施放不再享受效果；回到该方案恢复。已施加到目标上的限时增益按原生快照，不强制清掉其他队友的Buff。
