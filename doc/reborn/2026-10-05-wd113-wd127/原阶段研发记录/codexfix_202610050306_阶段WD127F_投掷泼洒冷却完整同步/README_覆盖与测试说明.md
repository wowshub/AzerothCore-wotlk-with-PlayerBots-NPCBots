# WD127F 投掷／泼洒冷却完整同步累计候选包

本包累计整合 WD127B 源码与双端数据、WD127C 六节点显示，以及 WD127E 图标／冷却相关修改，并修复此次四处遗漏。已经安装 WD127E 的用户也需要本包的源码、插件、客户端 Spell.dbc 和服务端 Spell.dbc；只覆盖插件不会修复动作条倒计时。旧包不需要逐个重装。本包不是实机验收结论。

## 本次实际修复

1. 药水投掷 9003870–9003876、泼洒药水 9003890–9003896：在 SPELL_GO 之后清除客户端预测的基础计时，发送服务端已存储的真实剩余冷却。原先只在 SPELL_GO 之前发送，客户端随后又用 DBC 的 15 秒启动动作条计时。沿用已存在的迅捷召唤／贡克祝福同类修正，不重复扣减，不改全局 GetSpellCooldown/GetActionCooldown。
2. 药水投掷的数字回包补齐第十个占位符。此前传了冷却参数，格式字符串却少一个字段，Lua 接收不到 e，回退为 15 秒；泼洒已有该字段。
3. 提示同时处理左侧说明与右侧“冷却时间”标题，支持中英文、原生提示重建、切换方案和过期响应。等待服务端时显示同步中。丛林蘑菇独立技能不再被附加一个假的 15 秒药水冷却。
4. 双端独立 Spell.dbc 的私有被动 9003897，EffectBasePoints 第80列由 -5001 修成 -5000。实际第74列 EffectDieSides 是0，所以旧值直接产生 -5001 毫秒，不会自动加1；第86列是施法目标，不能当骰子字段。修复后基础15000减5000等于10000，消除 9.999秒。两端每个文件仅此字段改变，字符串和其他记录保持原样。

## 覆盖步骤

1. 退出客户端，备份当前源码、客户端插件／Patch-XA、服务端数据。将 `01_覆盖到源代码根目录` 内文件覆盖当前源码工程，重新编译；编译后的服务端由你替换并重启。
2. 将 `02_覆盖到客户端根目录` 内文件覆盖客户端同路径。插件和客户端DBC两者都需要更新。
3. 将 `client_mpq输入_导入现有Patch-XA/DBFilesClient` 按相同内部路径导入当前使用的 Patch-XA。服务端停服后，将 `03_覆盖到服务端根目录` 覆盖到服务端根目录；客户端和服务端的 Spell.dbc 不可互换。完全重启客户端和服务端。
4. 本次修复没有新增SQL；已经安装到WD127E不用重导SQL。包内 `server_SQL` 是此前累计资料，仅给尚未装前批数据库的情况使用，按原先对应库要求安装，不用于修复这次计时。

## 一次验收两项技能

保存并激活有药水投手的酿造方案。等旧冷却结束，分别施放药水投掷和泼洒药水：

| 检查位置 | 药水投掷 | 泼洒药水 |
|---|---|---|
| 提示标题、说明、绿色当前值 | 10秒 | 10秒 |
| 动作条转圈及倒计时 | 约10秒起计 | 约10秒起计 |
| 提示“剩余冷却” | 跟随动作条真实剩余时间 | 同左 |
| 持续治疗buff | 蘑菇配料18秒 | 蘑菇配料12秒、每3秒一次 |

切换到没有药水投手的已保存方案，等当前冷却结束后新施放，两种药水恢复15秒。已有冷却不会因换方案被免费清掉；不要把旧施放计时当成新方案计时。HoT持续时间独立于技能冷却，因此10秒冷却与12秒／18秒buff不要求数字相等。倒计时插件显示整数时可能有取整差异，但不能仍从15秒起计。
