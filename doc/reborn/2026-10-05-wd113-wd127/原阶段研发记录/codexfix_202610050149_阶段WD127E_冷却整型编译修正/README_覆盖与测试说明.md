# WD127E 冷却整型编译修正

WD127E 替代 WD127D。本包继承WD127D的药水投手图标、实际冷却和客户端提示同步，只修复两处冷却表达式的C++类型错误。

## 报错原因

SpellInfo::RecoveryTime 声明为 uint32，rec/cooldown 是 int32。WD127D写 std::max(0, RecoveryTime - 5000)，其中0是int，后一个参数是uint32，模板无法推导同一种类型；外层std::min随之报错。源码共有两处，同一错误重复出现。先修复这两个编译错误，再重新生成modules；modules.lib缺失很可能是模块未构建成功的连带错误。

两处改为显式使用 std::min<int32>/std::max<int32>，并在减5000之前将RecoveryTime转换为int32。这还避免了小于5000时无符号减法绕回一个大数。药水实际15000毫秒保持缩短到10000毫秒，已经被修饰到10000时不会再减至5000。

## 覆盖

1. 已覆盖WD127D的用户：将本包01_覆盖到源代码根目录内两个完整源码文件覆盖当前工程，再重新编译。保留WD127D已装客户端文件；本包02里的两个客户端文件与WD127D完全相同，可跳过再次覆盖。
2. 尚未装WD127D的用户：在WD127B累计源码上覆盖本包01，并覆盖本包02到实际运行客户端。Data.lua包含WD127C六节点显示修正。不需重复叠加WD127C/WD127D。
3. 编译成功后重启服务端。客户端有更新时完整退出重启。无需SQL或双端DBC/MPQ更新。等旧冷却结束后，保存激活药水投手，新施放投掷和泼洒应从约10秒开始；未点该节点的方案应为15秒。

## 验证边界

使用本机MSVC 14.44.35207对独立类型复现文件执行 /Zs /std:c++17 /W4 /WX：旧表达式复现两组std::max/std::min C2672错误；修正表达式通过，退出码0。十条编译期断言确认15→10秒、已减为10秒不重复扣、已有更短8秒保持8秒，以及低于5秒/0值没有无符号下溢。只检查本次表达式，没有执行完整工程构建或游戏实测。四个安装文件中仅两个CPP各替换一行，客户端两文件与WD127D哈希一致。

rollback_WD127D是本轮两个CPP修改前副本；原rollback继承WD127D更早的回滚文件。详细编译日志、类型探针和文件哈希位于checks目录。

## 继承的WD127D功能及来源记录

# WD127D 药水投手图标与实际冷却修正

用户实测：药水投手保存后，泼洒药水技能提示与动作条仍是15秒；天赋图标和强效混合重复。WD127C只有节点可见性修正，本包补实际效果与客户端同步。

## 发现与修正

- 本地官方 CoA 20260925 Spell 705862 的 SpellIconID 为2020，路径 `Interface\Icons\Spell_Nature_Regeneration_02`；本项目被动9003897的SpellIcon也为2020。天赋树35065改用该图标，与技能书一致；不再复用强效混合的图标。无需新BLP或修改DBC。
- `Player.cpp`在9003897光环存在时，对9003870–76投掷和9003890–96泼洒精确限制最终冷却为至多10000毫秒；原生修饰若已生效不二次减5000。向客户端发送该技能最终冷却包，动作条应从约10秒开始。
- `.wd114numbers`为这14个等级新增服务端实际冷却字段；NumericTooltip.lua用它改写技能书／动作条提示的静态15秒，动态行也显示当前冷却。其他WD114数值格式保持兼容。
- 布局：当前客户端Data.lua沿用旧版酿造树，官方20260925整树节点和连接与其不同。WD127C把35065临时置于相邻空格(2,1)；本包只修该节点图标与冷却，不宣称整树布局已按新版CoA重建。新版官方坐标35065=(2,2)，旧树同格已有7131，直接覆盖会使两个节点重叠并影响旧加点。

## 覆盖

从 WD127B 累计源码与 WD127C 客户端面板修正继续。先备份当前源码和客户端插件；`01_覆盖到源代码根目录` 覆盖源码后自行重新编译、重启服务端，`02_覆盖到客户端根目录` 覆盖运行客户端后完整退出重启游戏。无需再执行SQL或导入DBC/MPQ。本包Data.lua累计WD127C六节点，未装WD127C也可直接覆盖本文件，但其余WD127B文件仍需在位。旧的15秒冷却先等待结束，再新施放测试。`rollback`为本轮修改前四个文件；回退角色方案数据仍以数据库备份为准。
