# 高版本区域完整移植(流放者之岛实战总结)

目标(用户 2026-11-26)：**一次移植完整**。地图能进、任务能做只是一部分；原版的人物和怪物形象、经验、掉落、金币、强度要在同一轮里考虑进去，不要等用户测出来再逐项补。

开工前先按 [CHECKLIST](references/CHECKLIST.md) 建表，每项写"做了 / 不做(原因) / 候选 / 用户实测"。

## 阶段顺序

### 0. 摸底与台账
- 按 audit-and-port-upstream-features 查来源。建任务台账、NPC/怪物清单、物品清单；每个阵营分开。
- 先回答：几个阵营、几张地图、有没有副本、过场、载具、职业任务；出区域时目标等级。

### 1. 客户端地图
见 [port-retail-map-to-custom-client](../port-retail-map-to-custom-client/SKILL.md)。关键：新建 Map 行且资料片字段 ≤ 服务器；AreaTable/LiquidType/WorldMapArea 补行；扫所有 WMO 水类型。

### 2. 服务端基础
- Map.dbc 双端同一行；地面数据(.map)先做，否则 NPC 下沉；vmaps/mmaps 见 find-and-extract 技能。
- 墓地、灵魂医者、死亡复活点；走得出地图的缺口用落石或门堵住(先量整个门洞)。

### 3. 任务链
见 [port-retail-quest-chain-to-wotlk](../port-retail-quest-chain-to-wotlk/SKILL.md)。
- 每批 3–6 个任务，用户测过再下一批。
- 两阵营同一批坐标：部落友方相位 1、联盟 2、怪物和公共物体 3；脚本给另一阵营设相位。新出生点默认相位 1，漏改另一阵营看不见。
- 克隆另一阵营以对方**最终状态**为底稿；点击物体按阵营复制模板；同一生物事件只放一个脚本，用阵营表分支。
- 过场动画见 [port-retail-cinematic-to-wotlk](../port-retail-cinematic-to-wotlk/SKILL.md)；多版本逐个试。

### 4. 人物、怪物、首领形象(第一遍就用原版)
见 [find-and-extract-retail-resources-for-wotlk](../find-and-extract-retail-resources-for-wotlk/SKILL.md)。
1. 逐个查零售 CreatureDisplayInfo：`ExtendedDisplayInfoID=0` 的**直接导入原版模型**；定制外观人形暂用替身并写明清单。不要先全部用 3.3.5 替身，用户会认为"不是正版"。
2. 别名虚拟路径一律 `retail\名字\名字.m2`(带外部骨架时必须，否则身体扭曲)；继承父骨架的还要查别名动作编号。
3. 同一模型靠部件组区分兵种：客户端 `ApplyMonsterGeosets` 只在某组的 4 位**非 0** 时隐藏整组再显示指定款；**0 表示整组全部保持显示**。零售没指定的组要填不存在的款号 `0xF`。
4. 离线渲染站立/移动/攻击/说话；渲染和检查脚本必须按**客户端规则**算可见部件，并核对每个可见部件的贴图槽都有贴图(否则白模)。
5. 缩放按零售；首领要有首领体型(守卫不能和首领一样大)；`creature_model_info` 的 combat_reach 要除以缩放，否则近战够不着或打太远。
6. 检查客户端补丁里是否有打包版零售文件抢先、Codex 是否改过同一张表(核对哈希台账)。

### 5. 数值：强度、经验、金币、掉落(和任务同批交付)
- **强度**：用核心公式和 `creature_classlevelstats` 估血量与伤害，对比原版同级(`references/mobsim.py`)。流放者之岛移植时普通怪伤害只有原版一半，首领血高到单人打不过——要写给用户决定单人还是组队。
- **任务经验**：移植任务不要把 `QuestLevel` 写成 1(经验按等级差打折，几乎归零)。用 -1 或按进度给等级，先用核心公式模拟出口等级(`xpsim.py`、`xpsim2.py`)再定档位和 `ExperienceModifier`。
- **掉落与金币**：新建的 `creature_template` 默认**没有** `lootid`、`mingold`。同批给齐：
  - 零售 `creature_loot_template` 过滤成 3.3.5 存在的物品(往往只剩灰色杂物)；
  - 按等级分档补**能穿的初始装备**(护甲和各类武器)，新手区野兽也可掉；
  - 稀有/头目有绿装几率，副本首领必掉；金币按原版同级怪；
  - 任务物品行和普通掉落用 `Comment` 区分，便于撤销和重跑；
  - 死亡后脚本立刻传送玩家的首领不要放掉落(捡不到)。
- **任务奖励装备**：零售很多装备来自任务奖励，本次没做；下次在台账里单列并决定。

### 6. 面向玩家的收尾
- 地图/小地图任务标记；对话处理函数不 `return false`；文本双语。
- 职业穿戴：掉落按档次随机时会掉出本职业穿不了的甲；经典模式要有限制(本次用 `ClassArmorRule.lua`，ALE 事件 31；登录载入也走该检查，会把不合规的已穿装备邮寄回去)。抽卡模式按用户要求不限。
- 新种族能不能接岛上任务、出区域后的职业任务、能不能从建角直接选这里出生(归 Codex，写交接)。

### 6b. 区内训练师和任务载具(已踩过的坑)
- **区内学技能**：直接用原版训练师机制(npcflag 48、`creature_default_trainer`，右键开窗)。要"一个位置、按职业"时，各职业导师同点刷新，用对象可见性条件(`conditions` 来源 30、`CONDITION_CLASS` 职业掩码)让玩家只看见自己的；GM 模式会看到全部。技能表可取同职业原版训练师并集。
- 本项目实测两种脚本做法都**没有弹出训练窗口**：隐形不可选 NPC 作列表主人(V1)、切换编号后 ALE `SendTrainerList`(V2，脚本确认执行到调用处)。根因未查明，不要再用。
- 排查时先让用户用原版对象对照(如 `.npc add temp <原版训练师>`)，能开说明客户端正常，问题在自己的做法。
- **任务载具要限制使用**：点击条件(来源 18：`QUESTTAKEN` 且目标进度未满)控制谁能上；伤害限制用全局钩子 `RegisterAllCreatureEvent` 10/11 让载具只伤任务怪。不要用按编号的生物事件(会换掉载具原 AI)；`ALL_CREATURE_EVENT_ON_DEAL_DAMAGE` 可注册但本 ALE 版本不调用。
- **复活点**按每个战斗区域检查：核心取同一地图直线最近的墓地，缺点时会送到墙另一侧的副本入口。重装早期 SQL 时注意阵营相位。

### 7. 验收与交付
- 每个包：安装步骤、SQL 开头和末尾读回值、输入/输出哈希、撤销、传送坐标测试表、与零售的差异、未测项。
- 给用户一条 **1 级新号走完整条线** 的测试路线：出口等级、金币、装备、打不过的怪。
- 助手不读数据库凭据、不执行生产 SQL；用户部署。验收按用户原话分项记，发布见 release-tested-reborn-features。
- 发布附件只放自己写的文本；过场、零售模型、DBC 不上传。

## 踩过的坑(速查)
| 现象 | 原因 | 做法 |
|---|---|---|
| NPC 沉下去、掉进深渊 | 没有地面数据/建筑内无碰撞 | 生成 .map / vmaps；临时飞行式移动 |
| 任务一接就完成 | 计数生物没建 | 查 Errors.log |
| 对话菜单被默认问候盖住 | ALE 返回 false | 什么都不返回 |
| 改过的内容又变回旧版 | 重跑早期 SQL | README 写明顺序和重跑影响 |
| 人物说话时身体横过来 | 别名路径不是 retail\ | 改路径，离线渲染动作 |
| 模型白色部件、部件叠在一起 | 部件组填 0 | 填 0xF，按客户端规则检查 |
| 怪不掉东西 | 没给 lootid/金币 | 同批给齐 |
| 做完整条线才几级 | QuestLevel=1 | -1 + 模拟 |
| 首领掉落捡不到 | 死亡即传送 | 不放掉落或改脚本 |
| 牧师穿上锁甲 | 熟练度来源未查明 | 穿戴事件按职业拦截 |
| 判断"新种族接不了任务"出错 | 只查数据没查核心代码 | 先读 PlayerQuest.cpp |
