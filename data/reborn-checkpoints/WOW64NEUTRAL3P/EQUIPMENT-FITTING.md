# 私有身体衣物与披风的挂载

2026-11-21 用户确认 3N 恢复了大多数种族的身体装备，随后确认 3P 披风、人物面板和幻化修复可以提交和推送。验收以本次角色及装备组合为准，跑跳穿插和所有装备款式仍需专项复测。

## 先查运行时模型身份

只有头盔、肩膀和武器显示时，分别检查独立挂件和胸甲、裤子等身体衣物。用实装 MPQ 验证身体与衣物文件的骨骼、父子关系和枢轴。日志记录请求路径、实际缓存返回的路径、父模型和骨骼数量。贴图已经合成、磁盘骨架逐骨一样、运行时却反复出现 skin-rejected 时，优先核对模型缓存。

这次七份私有衣物都叫 clothing.m2。旧 CM2Cache::CreateShared 默认按文件名缓存，女妖先加载就会把它的骨架和网格交给随后加载的种族。用现有的 0x10 完整路径缓存选项创建这类衣物。3N 回归直接执行客户端缓存查找函数，旧行为可复现，新行为覆盖全部 5040 种顺序，重复请求仍复用自己的模型。

## 从装备到世界画面

1. 从实际 ItemDisplayInfo 解析装备组件贴图。异步就绪后合成保留透明度的衣物图集，用衣物自己的 type 14 槽。披风使用 type 2 和专用分段，可选披风未就绪时先让衣物显示。
2. 身体与私有衣物都就绪后，在已知的根挂点建立 SetSkinParent。用身体当前姿势矩阵驱动衣物。逐骨检查层级、名称、枢轴和权重调色板。只有经过核对的完整骨架副本才允许使用按索引的兼容路径。
3. 从绑定日志、可绘制状态、绘制队列、实际 draw 分别定位。一次 queued-opaque 表示已提交满不透明度绘制，最终屏幕效果还取决于纹理、几何体和深度。普通模型切换、换装和冷启动都要实测。

## 人物面板、幻化和披风

人物属性面板和试衣主模型会 DuplicateModel。复制附件后一并重建源模型中有效的 skin-parent，绑定预览自己的身体。只复制挂点、贴图或装备 ID 会让衣物保留自己的姿势，表现为胸甲、裤子和披风掉到模型原点附近。

幻化缩略格单独处理。受影响种族的护甲格复用 SetHumanPreview 标准试穿模型，切武器格时清理该状态。玩家左侧主预览用实际角色。回归覆盖翻页、换槽、武器和护甲切换。

披风像纸片时，按实装背部的领口、腰线和侧边取样，仅调整独立披风分段顶点、法线、UV 与包围盒。3P 保留了孢子人、猴子、骷髅原衣物几何、骨骼调色板和权重。披风缩短并沿背部弯曲。按完整路径回读 MPQ，验证其余条目未被覆盖。披风仍随身体骨骼驱动，拉扯和碰撞要单独验收。
