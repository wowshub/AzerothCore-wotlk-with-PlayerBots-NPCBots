# 为什么“不是空指针”也会崩溃

把 Unit* 想成房间地址，GUID 想成身份证。目标下线后房间可能拆掉，旧地址仍然不是零；到旧地址问“人还在吗”本身就可能崩溃。原来的 value && value->IsInWorld() 就是在旧房间敲门。

Set(Calculate()) 在本次正常选择目标后立即提取 GUID；此时调用方必须提供有效对象。后续读取只拿 GUID 到 ObjectAccessor 查询当前地图对象，不通过旧 value 读取 GUID 或状态。查询失败返回 nullptr，机器人本轮不执行依赖该目标的动作。查询成功后才检查 InWorld 和正在移除标志。

选择主坦克可能要遍历队伍和职责，原来的两秒选择间隔保留；中间每次只做身份查询。Get 是正常读取；LazyGet 保留不主动到期重算的语义，但仍重新查询对象；RefGet 为旧接口重新填返回槽，调用方不得跨帧保存此引用，改变目标要调用 Set；Format 使用 Get 展示当前安全查询结果；Reset 清空身份并让下一次读取重新选择。value 仅用于返回，不再是对象身份来源。

uint32(now-lastCheckTime) 使用无符号模运算，使毫秒计时器回绕时仍能计算短间隔。cacheInitialized 独立表示是否已经计算，避免把时钟等于零误当未初始化。

本包没有改动光环数值、施法条件或数据库。Claude 的 NPCB1A 修的是 NPCBot 宠物保留主人地址，本包修的是 AI 目标缓存，两者都是对象寿命问题，但不能互相替代。

检查采用三层：实际源码与调用链自审；5 个真实 C++ 翻译单元 /Zs；独立 Python 模型用已释放标记、对象注册表和时间窗口覆盖边界。模型不是游戏引擎，因此最后必须由用户在真实队伍上线下线、跨图和技能施放中验证。未实测不得登记为成功 Skill。
