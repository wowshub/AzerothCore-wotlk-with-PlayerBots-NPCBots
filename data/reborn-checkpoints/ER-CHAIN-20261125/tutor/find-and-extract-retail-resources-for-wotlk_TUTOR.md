# Tutor：怎么找、怎么取零售和别的服务器的资源(find-and-extract-retail-resources-for-wotlk)

对应 Skill：`beascendskills/find-and-extract-retail-resources-for-wotlk`。大白话。

## 先打个比方
- **零售客户端**是一个巨大的仓库，东西按"编号"存放(文件编号 FDID)，不是按名字。
- **数据库和 wago.tools 的表**是仓库的"目录"：告诉你"野猪的外观编号 → 模型文件编号"。
- **listfile** 是"编号 ↔ 文件名"的对照表。
- **我们的客户端(3.3.5)**是一个老仓库：只认老格式，东西要先"改装"才能放进去。

## 找东西的顺序(照这个来)
1. **先问：客户端里是不是已经有了？**
   - 比如绷带法术、侏儒直升机外观，本来就在。能用现成的就别导入，省事、不容易出错。
   - 用 `references/lookup.py 名字` 在服务端基础库里按名字找外观。
2. **没有，再去零售里找。**
   - 任务、NPC、出生点、掉落 → 数据库 `LoreWalkerTDB`(`world.sql`)。
   - 物品、生物外观、模型数据 → wago.tools 的 CSV(搜 ID)。
   - 想知道某个编号对应什么文件 → `listfile.csv`(搜名字或编号)。
   - 文件本体(模型、图标、地图) → 本地零售客户端，用 `RetailAssetProbe.exe` 按编号提取。
3. **提出来以后，要"改装"。**
   - 图标：转成 3.3.5 能读的 BLP(`blp_dxt1.py`)，必须带"缩小图"(mip)，不然显示成绿色。
   - 模型：登记别名(`aliases_maps.csv`)，客户端补"模型表+外观表"各一行，服务端也要补，还要补"生物模型信息"，否则看不见。
   - 地图：转成 3.3.5 地形，客户端按地图技能那一套做，服务端用 `map_extractor` 生成地面数据。
4. **改完要对"赢的那一份"动手。**
   - 客户端同一个表被很多补丁包盖来盖去，**最后加载的那份才生效**。动手前先查哪份赢。
   - 改完把前后的校验值记进台账，别人(Codex)也在改同一张表时按"编号"各加各的行。
5. **进游戏前的"三关"**：关掉 MPQ 编辑器(它会锁住文件)、清客户端缓存、重启服务端。

## 地图这件事怎么理解(最容易糊涂)
- 客户端要的是**看得到**：地形、建筑、水。
- 服务端要的是**站得住**：地面高度，没有它 NPC 会往下沉。
- 建筑的碰撞(vmaps)、怪物自动寻路(mmaps)是更后面的事，我们**还没做**。
- 每一块地 533 码见方，文件名里的数字是格子编号，用坐标换算，不要靠猜。

## 去别的服务器找资源(**候选做法，我们没实测**)
1. 把对方的补丁放到**一个新文件夹**，不要放进你的游戏目录。
2. 用 StormLib 工具列出里面的文件，搜关键字(比如 `creature\xxx`)。
3. 取出来先在独立副本里看格式对不对。
4. 看许可证：能不能用、要不要署名。
5. 导入时一样要补"模型表/外观表/服务端模型信息"。
> 这一段是推荐流程，没有真的走过一遍，第一次用要边做边记录。

## 不知道怎么搜时
1. 按**编号**搜(最准)，再按名字搜。
2. 名字在 3.3.5 里常叫法不同，先用现成的外观"替身"代替。
3. 找不到就写下"查了哪些地方、没找到"，不要编造。

## 检查清单(给自己)
- [ ] 查过客户端里是否已有。
- [ ] 知道哪份表会赢。
- [ ] 客户端和服务端两边都补了。
- [ ] 登记了校验值。
- [ ] 关了 MPQ 编辑器、清了缓存、重启了服务端。
- [ ] 写清了哪些是用户测过的，哪些没测。

## 2026-11-25 补充：为什么怪会“掉进深渊”
客户端看得到建筑，服务器默认只知道地面高度。把零售建筑也转换给服务器(vmaps 管挡视线和脚下的地板，mmaps 管怪怎么走路)以后，服务器才知道楼层在哪。转换时一个坑：大建筑拆成很多块，必须和总文件一起转，否则后面的块是错的而且不报错。
