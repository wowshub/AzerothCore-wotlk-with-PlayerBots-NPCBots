# Tutor：把零售任务链搬到我们的 3.3.5 服务器(port-retail-quest-chain-to-wotlk)

对应 Skill：`beascendskills/port-retail-quest-chain-to-wotlk`。面向第一次做的人，大白话，一步一步来。

## 先想明白一件事
零售(12.x)和我们的服务器(3.3.5)是两个"语言不通"的游戏：
- 零售的任务表里写的是"任务目标是什么"，3.3.5 的任务表只认"杀谁几个、拿什么几个"。
- 零售里有载具、阶段、场景、过场，3.3.5 没有。
- 所以**不是复制粘贴，是"翻译"**：每个任务目标想一想，3.3.5 里用什么办法做出同样的感觉。

## 操作流程(照着做)
1. **先列清单，不要先写代码。**
   - 打开 `references/scripts/ledger.py`，改路径，指定任务 ID 范围(流放者之岛是 59926~60100)，运行。
   - 得到：每个任务的标题、上一个任务、下一个任务、谁发任务、谁交任务。
   - 把它抄进台账文件，一个任务一行，写"打算怎么做"。
2. **一次只做一小批**(3~6 个相邻的任务)。
   - 用户测通过，再做下一批。一次做太多出了问题没法查。
3. **把零售数据提出来。**
   - 运行 `exbatch.py 输出.json 59929,59930,59931`，里面是任务文字、目标、NPC、出生点、掉落、任务物品。
   - 打开 json 看一看，心里有数：这批要几个 NPC、几个怪、几个物品。
4. **逐个目标"翻译"**(看 Skill 里的对照表)：
   - 杀怪 → 填"需要杀的怪和数量"。
   - 拿东西 → 怪掉落里加一个"任务专用"物品。
   - 和人说话 → 写一小段 Lua，对话时给任务进度。
   - 对 NPC 用物品 → 让物品有一个"使用效果"，Lua 在使用时给进度(急救包就是这么做的)。
   - 飞行/载具/动画 → 用"乘客飞行"或客户端小插件模拟，先当实验，一定要用户测。
5. **NPC 和怪**：
   - 编号一律"现有最大编号 + 1"，不能超过 16,777,215，否则服务器一开就自己关掉(我们真出过事)。
   - 没有对应的 3.3.5 模型就先用现成的"替身"，别让它看不见；看不见通常是少了模型信息表。
   - 地上要有地面数据，不然 NPC 会往下沉。
6. **文字全部中英双语**(`English 中文`)。
7. **打包交付**：每次一个新的版本文件夹，里面有：SQL、Lua、说明、撤销步骤、哪些没测。已经给出去的包不改，要改就新建 V2。
8. **测试**：让用户按这个顺序测：能接 → 进度计数 → 交任务 → 下一个任务出现 → 重登 → 死亡复活 → 重启服务器后还正常。

## 最容易踩的坑(都是真遇到过的)
| 现象 | 原因 | 办法 |
|---|---|---|
| 服务器启动后自己关了 | 出生点编号太大 | 用"最大编号 + 1" |
| 怪/NPC 看不见 | 少了生物模型信息 | 补模型信息表一行 |
| NPC 沉到海里 | 没有地面数据 | 生成地面数据 |
| 背包图标是问号 | 客户端的物品表没这一行 | 补客户端物品表 + 图标 |
| 改了没效果 | 没清客户端缓存 / 服务器没重启 / MPQ 编辑器开着 | 逐项排除 |
| 点急救包落到自己身上 | 客户端"自动自我施法" | 脚本里处理"目标是自己" |
| 同一个人治了好几次 | 自动找目标时只看"在不在范围内" | 先排除已治疗的，再选最近的 |

## 判断一个功能"算不算做完"
- 用户在真客户端里测过，说"通过"才算。
- 没测的，在说明里明确写"未测"。BOOST1A(飞行)、篝火闪光(CAMP1A)目前都是这类。

## 想复用时怎么开始
1. 读 Skill 的"证据状态"，知道哪些已经证明能用。
2. 打开 `references/scripts`，改好路径，跑 ledger → exbatch。
3. 照上面的流程一批一批做。

## 2026-11-24 补充：今天验收通过的三件事，用大白话
1. **飞行侦察**：飞机本来没有"骑手座位"这个挂点，人上去就看不见。我们给飞机模型文件补了一个座位点，人就被"夹"在飞机下面了。飞行是自动飞完的，没有中途下来的按钮；任务只在你飞过尸骸群上空再落地时才算完成。
2. **篝火提示**：给篝火设成"任务物体"，对没完成任务的玩家会发光，鼠标换成发光手套的光标。
3. **缩放器**：物品点一下→出现目标光标→点野猪。关键经验：**别沿用零售物品编号**，我们的客户端对零售编号 178051 就是不认使用效果，换成 9 开头的自己的编号立刻好了。野猪变大前先记下它本来的大小，变回时恢复这个值，别写死一个数。

## 2026-11-25 补充：任务链收尾时踩的三个坑，用大白话
1. **“一接就完成”**：任务写着“要完成一件事”，但那件事对应的隐形计数怪从来没建。服务器看不懂就把这个要求划掉了。启动日志里其实早就写了，所以每次装完先看一眼 Errors.log。
2. **对话选项不见**：脚本最后多说了一句“我没处理(return false)”，服务器就好心地又弹了一个默认问候框，把我们的选项盖住了。
3. **改好的文字又变回去**：把更早的安装脚本又跑了一遍。后面的改动是叠在前面之上的，顺序不能倒。
