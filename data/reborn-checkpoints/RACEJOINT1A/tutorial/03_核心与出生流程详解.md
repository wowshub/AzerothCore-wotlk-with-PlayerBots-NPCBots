# 第三课：核心代码为什么这样改

本课实际代码在“逐行讲解”中，下面先给阅读地图。所谓函数，就是把一个问题包装成有名字的小步骤；参数是给它的信息，返回值是它给的答案。`bool`只有真/假，`uint8`是0–255整数，`uint32`是32位无符号整数；`nullptr`表示没有对象。

## 六个文件各管一件事

| 文件/函数 | 输入→输出 | 本次修改的用处 |
|---|---|---|
| SharedDefines.h / GetRaceMaskForRace | 真种族ID→资格位 | 避免超过31位的移位；36/37仍0，39/49按批准规则复用位 |
| SharedDefines.h / GetRaceAliasTemplateRace | ID→模板1/2或0 | 声明39借人类、49借兽人的有限基础模板，不改变真ID |
| SharedDefines.h / GetReputationRaceMaskForRace | ID→声望默认位 | 两族读取本阵营基础声望，避免拿共享位侏儒/艾瑞达当身份 |
| RaceMgr.cpp / LoadRaces | ChrRaces→可用集合及日志 | 共享位的两个种族必须同阵营，缺母行或阵营相反就不开放 |
| DBCStores.cpp / GetSkillRaceClassInfo | 技能+race+class→首个合格行 | 别名族不继承单一种族位的特长行；保留通用/多族技能 |
| ObjectMgr.cpp / LoadPlayerInfo | WORLD出生行→内存出生资料 | 三处加载入口都排除别名族按共享位吃母族专属技能/法术 |

## 为什么39会和7共用64

32位掩码像一排32个开关。race1用第0位，race7用第6位。`1 << 6`=64。39计算`(39-1)&31`=6，49计算`48&31`=16，所以`1<<16`=65536。`&31`保留低5位，效果是对32取余。位编号从0开始，种族编号从1开始，所以先减1。

但“共用开关”不等于“同一个人”。数据库仍保存39/49，模型仍加载各自ID；只在旧32位资格接口兼容。共享位会造成别族单行误匹配，因此同时过滤出生技能、SkillRaceClassInfo、SkillLineAbility；任务、物品等其他按位系统还要专项核对。不能以为一个取余函数修好全游戏。

`mask & (mask-1)`的用途：若只有1个位亮，结果为0；若至少2个位亮，结果非0。例64 &63=0，65 &64=64。这里用它区分单族专属行和多族共享行。它只是兼容筛选，不证明任何多族行都适合任意未来种族。

36/37走既有mask0的显式路径，不跟39/49一起改为取余。这是本项目已经验收过的约束，不可因“统一好看”顺手重写。

## 出生顺序，像先领驾照再交钥匙

真实顺序：`Player::Create` → `LearnDefaultSkills` → `LearnCustomSpells` → 动作条 → `CharStartOutfit`物品 → 后续创建回调。

这里的后续创建回调就是`OnPlayerCreate`。如果等这个回调才补武器/护甲技能，物品分配已经结束，角色有装备也可能只在包里；因此本次必须在核心的`LearnDefaultSkills`里提前处理。

修法是在LearnDefaultSkills中、仅战士、仅39/49，读取同阵营模板已有技能；再限制在17项白名单里；已有的HasSkill不覆盖。结果是物品发下来时角色已经会用，不必等登录。

白名单：26/256/257战士技能页；95防御；162徒手；43剑、44斧、54锤、55双手剑、160双手锤、172双手斧、173匕首、176投掷；413锁甲、414皮甲、415布甲、433盾牌。这不是一次性赠送列表：还必须模板出生资料本来就有该条。骑乘、专业、双持、高阶护甲不在本次授予范围。

`SetSkill(languageSkill,0,300,300)`：技能ID、技能阶段、当前熟练值、上限。语言按既有契约300/300；不能把同样300/300照抄给所有武器，否则把练级过程直接练满。

39的语言skill98 + spell668；49为109 +669。技能ID与法术ID是两张不同表的号码，不能只填其中一个。创建前不在世界，使用addSpell注册；已经在世界才走learnSpell的正常通知路径。

## 恢复模块为什么还要保留

`FindProfile`先按真实race及class1找规则；`CheckPrerequisites`检查种族可玩、阵营、容量、掩码、出生资料、语言Spell与SkillLineAbility链接，缺任何一项就返回错误文本。`Synchronize`先检查玩家和开关，再检查所有缺失技能是否有资格，全部检查完才授予，避免修到一半才发现后半不能修。

`getRace(true)`使用真实种族，避免变身/外观伪装干扰；`std::find`避免模板重复行重复授予；`HasSkill/HasSpell`保证重登不重复发。已存在的技能数值不会下降或被练满。模块不发物品、不初始化声望、不清包、不强行修所有种族；新建自动穿装靠核心先后顺序。

`PlayerScript`是服务器回调订阅；构造函数登记ON_CREATE和ON_LOGIN；两个override都调用同一个Synchronize，避免两份修法日后不一致。`AddRebornCoaBirthScripts`让模块被加载器注册，CMake还要登记config，否则文件放在configs/modules也可能没读到。dist默认false，测试用实际conf=1；不要把“模块编进去了”当“模块运行开关已打开”。
