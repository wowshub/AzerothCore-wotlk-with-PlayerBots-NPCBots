# 补课：看代码前先认识符号，再看整条链

## C++的一小段真实代码

```cpp
inline constexpr Profile const* FindProfile(std::uint8_t race, std::uint8_t playerClass)
{
    if (playerClass != 1)
        return nullptr;
    for (Profile const& profile : Profiles)
        if (profile.Race == race)
            return &profile;
    return nullptr;
}
```

第1行声明函数。FindProfile是名字；括号里race、playerClass是输入。`std::uint8_t`精确为8位无符号整数，0–255，够放39/49。前面的`Profile const*`表示返回“只读Profile规则的地址”。inline允许这份头文件定义在多个源文件中被引用；constexpr允许符合条件时在编译期算结果，不要求一切运行时数据都预先存在。

第2行花括号开始函数体。第3行`!=`是不等于，若职业不是1；第4行立即return空指针，后面都不走。它是“这条规则不适用于你”，不是崩溃。

第5行范围for把Profiles数组逐个拿出来叫profile；`const&`是引用现有对象且不让修改，避免每次复制一份。冒号右边是被遍历的数组。第6行`.`读结构成员Race，`==`比较是否相等；不要与单等号赋值混淆。

第7行`&profile`取那条规则地址返回；因为Profiles是编译期固定数组，不是函数里临时创建的局部对象，这个地址不会函数返回就失效。第8行循环没找到才返回空。第9行闭合函数体。

调用者要先判断profile是否为空才能`profile->Race`。`->`是通过指针访问成员，`.`是直接对象访问成员。你在历史崩溃里看到`GetBattleground()->...`，正是应先确认返回对象存在的同类问题，但本窗口没有把那条旧战场崩溃重新归因或重修。

## 条件运算最容易看错的地方

`&&`是两边都成立；`||`是至少一边成立；`!`是否定。会短路：`!player || ...`中player为空时后面不用读成员，可以避免空指针。`&`单个符号是按位与，和逻辑&&不是同一件事。`|=`是把标志位并入当前集合。`?:`是短条件选择，条件真取前者、假取后者；GetRaceAliasTemplateRace据此返回1/2/0。

`mask & (mask-1)`是数学位操作；`HasSkill(id)`是调用一个运行时方法，不能当常量。`if`后没有大括号只控制紧接的一条语句；本次核心有嵌套if/for，阅读时按缩进/作用域配对，不给没有覆盖的分支脑补执行。

## Lua为什么长得不同

Lua用`local`定义局部变量，`nil`表示没有值；0是真值，不等于false。`and/or`既能做判断也常用于选择结果，所以点数0也应算“已有有效数据”。`f(x)`普通函数；`frame:Show()`冒号会把frame作为隐含self传入。`end`关闭if/for/function，不是每个end都结束整个文件。

`local oldRefresh=B.RefreshTree`保存函数值；新`function B.RefreshTree()`先调用oldRefresh再增强。`function(success,reason)...end`是回调函数，等异步任务结束才执行；不是定义完立即成功。

`build.ranks[id]=rank+1`仅改Lua草稿表；真正学习必须调用原生LearnTalent或自定义服务端协议并等确认。表有数据、图标亮金色都不是服务器学会的证据。

`ipairs`按数组连续顺序遍历；`pairs`遍历键值，不承诺推荐加点顺序。`#queue`读序列长度；`queue[#queue+1]=step`向末尾追加。`math.floor`向下取整；`math.min/max`用于把输入夹在合法范围。

## Python测试为什么能拼C++和Lua

Path表示路径，`/`拼路径不是数字除法；read_bytes读精确字节，read_text按编码变为字符串。`r"""..."""`或原脚本中的raw字符串用于装C++/Lua原文，不在Python里执行其括号。

test_birth_order按`{`深度+1、`}`深度-1截出完整生产块，再拼到C++替身中由cl实际编译运行。Lua测试把实际脚本交LuaRuntime，GetTalentInfo等API换成可控替身。Python只是导演，不是用Python重写了一份游戏核心。

`assert 条件,提示`失败会抛异常停止。`subprocess.run`启动工具，returncode为0才算这次成功；有一个上次残留EXE不代表本次成功。JSON报告存结构化检查结果；SHA256按字节识别原件。路径、编码、退出码都属于复现条件，不是可以随便省掉的琐事。

## 从初级到高级的练习顺序

1. 在Profile表读出39/49的语言两号码，手算39的掩码64、49的65536；解释36/37为什么不能照套。
2. 在LearnDefaultSkills找到`!HasSkill`，说明删除它为什么可能破坏旧熟练度。
3. 按Player::Create实际调用顺序画箭头，解释OnPlayerCreate为什么太晚。
4. 在模块找“先收集missing、再授予”，解释若第3个缺失技能资格不合法，第1个为何也不应先教。
5. 在天赋测试LearnTalent和ack之间加观察，解释草稿与服务器已学为什么不同。
6. 在离线测试里改坏一个掩码、删语言链接或模拟战斗，先预测哪条断言失败，再在隔离环境验证；不要改生产库。

这六步比背接口名字更重要：先说出预期→修改→看证据→知道证据没有证明什么。
