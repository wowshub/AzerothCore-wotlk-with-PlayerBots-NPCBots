# 自定义种族：让身体装备（胸甲/腿甲/手套）画到非标准 UV 的模型上

## 什么时候用

- 新种族模型自己展开了整张身体 UV（不是标准角色贴图的分区排布）。
- 现象：只有头盔、肩膀、武器、盾牌（它们挂在骨骼点上）能显示；胸甲、腿甲、手套、靴子不显示；或者打开衣服合成后衣服图盖到脸上（CoA 蛇人就是这样，Codex 的 RACECLASS1D 曾因此关掉合成）。
- 先看 [port-coa-race-appearance-wxl](../port-coa-race-appearance-wxl/SKILL.md) 判断外观槽和皮肤合成的基本关系；本 Skill 只管"装备画上去"。

## 已验证（用户 2026-11-08，蛇人男、女）

- 男性 v8、女性 v8：创建页和选角界面里，T7 装备的胸甲、腿甲、护臂、手套盖住了蛇皮；花纹左右对称、端正；头保持原版（有眼睛）；6 个肤色创建页正常。用户原话：男"这次 绘制的对称好看多了"，女"女性的也很棒"，随后"通过了 这个设计太棒了"。
- 男性 v7 进游戏截图：装备显示，跑动没有闪烁撕裂。
- **没有验证**：靴子、披风、长袍、袖子（模型没有对应几何体，不显示）；女性进游戏动作；长期游玩、全部装备组合；Codex 在 v8 男性 M2 上叠加背盾后的合并效果（办法已定，见下"合并约定"）。
- 代价（方法本身决定的，不是 bug）：没穿装备时身体的蛇皮是烘焙版，比原版糊，且左右镜像（左右细微不对称被抹平）；被自带装饰件压住的地方，装备被装饰件挡住。

来源包：`000Ascendupdate/000Ascendupdate20261108/claudefix_20261108_阶段SETHARMOR1A_蛇人男性装备叠加层试验_Claude`（v1~v8，`01i_v8` 为最终）与 `..._阶段SETHARMOR1B_蛇人女性装备叠加层_Claude`。脚本见 [references/scripts](references/scripts/README.md)。

## 合并约定（别的成员也要改这个种族的 M2 时）

- 以"用户客户端 YJ 里现在这份叠加层 M2"为底再叠别的改动（骨、挂点），不要从原版 M2 起步；他们的包只带这一个 M2，**不动叠加层的 skin、底图和 Bake 贴图**。这样用户不用还原也不用重导。
- 改完跑 `references/scripts/seth_overlay_guard.py <新M2> <底M2>`：必须输出 `OVERLAY INTACT`（贴图类型 [8,0,0,1]、贴图查找第 4 项=3、UV 集查找第 2 项=1、替换表第 1 项=3、顶点数 27292、身体顶点第二套 UV 与底一致）；它还会报告位置/权重/法线/UV1 有多少顶点和底不同（只改骨/挂点应为 0）。Codex 已按这个办法以 v8 为底出了包。
- 皮肤、底图、Bake 贴图、另一性别的模型，谁要改先登记并通知。

## 为什么装备画不上去（先搞清楚再动手）

| 事实 | 后果 |
|---|---|
| 胸甲/腿甲/手套/靴子是"画"在角色身体合成贴图（M2 贴图类型 1）上的；头盔/肩甲/武器是挂点上的独立模型 | 模型没有类型 1 贴图槽，或类型 1 的 UV 不是标准分区，装备就没地方画/画错地方 |
| 标准角色贴图（256 网格）：ArmUpper(0,0,128,64) ArmLower(0,64,128,64) Hand(0,128,128,32) Face(0,160/192…) TorsoUpper(128,0,128,64) TorsoLower(128,64,128,32) LegUpper(128,96,128,64) LegLower(128,160,128,64) Foot(128,224,128,32) | 装备贴图按这些矩形画 |
| **标准贴图左右镜像共用**：身体左边和右边是同一块纹理；躯干区域里正面在最左，背面在最右，两侧在中间 | 绕身体整圈取 UV 会让花纹斜、不对称（"像衣服穿歪了"） |
| **这个客户端合成出来的贴图没有透明度**：没画的地方是不透明的黑色；透明底图也不管用 | 透明混合的叠加层会把身体整体盖黑；相加混合能工作但装备发光 |
| 合成底图用的是 CharSections 的底图（类型 0 行的 Texture1）和 FL/FU/LU/TU（脸/内衣）贴图，它们会被先后画进合成贴图 | 它们必须是"能当底"的内容，不能是全零 |

## 方法（按顺序）

1. **证据**：解析 M2：贴图表（类型/名字）、贴图查找、UV 集查找（texUnitLookup，值 1 = UV2）、替换表（texReplace）、渲染材质；解析每个 skin：分区（id、顶点数、三角形范围）、批次（单贴图 alpha 层是什么样）；画侧视/正视图判断体型和 A 字站姿。男、女分别做，**不要假设一样**（女性的 UV2 已被特效层使用；皮肤文件批次数组不在文件末尾；女性 skin 原件在 YB 里）。
2. **保存真原件**：用户一旦导入试验包，客户端里读到的就是改过的文件。第一次就把原件存成 orig_true，之后每次都从它重建；备份包里放真原件。
3. **模型改动**（只追加，不删不改原有数据）：
   - 追加一个类型 1 贴图槽；追加贴图查找项指向它；替换表第 1 项指向它；
   - UV 集：男性追加查找项（值 1）；女性复用已有的值 1 项；
   - 给每个 skin：追加一个"只含身体本体"的新分区（见第 5 条），并把身体的"单贴图 alpha 层批次"复制一份：材质 0（不透明）、层 2、1 张贴图、贴图查找=新项、UV 集=UV2、分区=新分区。
4. **UV2 映射（左右镜像对称，只取决于到中线的距离）**：
   - 躯干：u = |方位角|/π（方位角 0 = 正面，π = 背面），v 按高度；上躯干/下躯干按高度分界；
   - 手臂：以手臂轴线（A 字站姿）为准，只用 x、z 平面的角度，两臂自然一致；上臂/前臂/手按沿轴位置；
   - 腿：角度按"外侧为正"（y 乘以所在侧的符号）；大腿/小腿/脚按高度；
   - 尾巴：角度用 |y|，沿长度为 v，映射到腿下部区域；
   - 头/脖子以上：不参与（见第 6 条），其顶点停在躯干区域顶部的黑边。
   - 女性：**只改身体顶点**的 UV2（身体顶点集 = skin00 最大的 id-0 分区），其他顶点（特效层在用 UV2）一个字节不动。
5. **只含身体的分区**：身体本体分区（id 0，且顶点与最大 id-0 分区重合 ≥90%；男性用"顶点数>250"也可）。在分区内把三角形重新排序（身体在前、头在后，画出的三角形一模一样），复制该分区，新分区的三角形数只含身体部分。分区数组和批次数组整体复制到文件末尾再追加，改头部里的数量和偏移（旧数组留作死数据）。
6. **头部排除**：头（男 z≥1.95，女 z≥2.05）不进叠加层也不烘焙，保持原版（眼睛、鳞片清楚）。教训：v6 把头也烘焙进标准布局的小区域，分辨率不够，眼睛丢了。
7. **自带装饰件不参与**：装饰件（id 101~104、201、301、401 和小件）的 UV 与身体重叠；一起烘焙会让装饰颜色盖掉蛇皮（"身上像裹了一层布"）。叠加层只复制身体本体的批次。
8. **烘焙合成底图**：把种族的颜色图集（本例 2048x512）按 UV1→UV2 对应关系光栅化成 512x512 底图：图集先缩小一半做预滤波，三角形逐像素取样，跨接缝的大三角形跳过，用邻近颜色膨胀 8 次，剩余用平均色填满。左右镜像意味着每对左右对应点只存一份颜色。
9. **写 BLP（关键）**：必须和原文件同格式——BLP2、调色板（type1 encoding1）、8 位透明、同样的 148 字节头和 mip 布局：复制原文件的 148 字节头，写新调色板（Floyd-Steinberg 抖动量化，mip 也用同一调色板抖动），透明通道全 255。长度必须等于原文件。
10. **脸/内衣 24 张贴图（FL/FU/LU/TU）**：换成烘焙底图的对应裁片（FU=(0,320,256,384) FL=(0,384,256,512) TU=(256,0,512,128) LU=(256,192,512,320)，512 坐标），不要留全零（会盖黑头/身体）。
11. **离线校验**（每次都跑）：M2 头部只有贴图/查找数组被改；所有顶点位置/权重/法线/UV1 不变；（女）非身体顶点 UV2 不变；每个原有分区画的三角形集合不变；原分区未改、新分区无头三角形；叠加批次指向新分区且材质/层/贴图/UV 索引正确；BLP 长度和头部等于原文件。**故意把一条检查改错确认校验能报错**。
12. **交付**：独立试验包，每个版本一个"只需导入这N个文件"的文件夹，真原件备份，说明里写回滚（注意 skin 原件在哪个 MPQ：女性 4 个 skin 原件在 YB，导入 YJ 是新增覆盖，回滚要删除而不是导回）。登记协作说明，改共享 M2 前核对 Codex 的改动。

## 踩过的坑（失败版本）

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 透明混合叠加 + 全透明 DXT5 底图 | 没装备的地方亮绿色 |
| v2 | 底图改成与原文件同格式的透明调色板 BLP | 绿色没了，但没装备处整层是不透明黑色（取下装备全身黑） |
| v3 | 相加混合 + 头挪到黑边 | 没装备时蛇皮透出；装备"发光叠加"，颜色偏亮 |
| v4 | 烘焙蛇皮进底图 + 不透明叠加 | 装备真正盖住；头被全零 FL/FU 盖黑 |
| v4b | FL/FU/LU/TU 换成烘焙裁片 | 头恢复但头罩有竖条拉伸 |
| v5 | 抖动量化 + 球面头映射 | 身体变成黄绿裹布（装饰件一起烘焙） |
| v6 | 只烘焙身体本体 | 装饰件问题解决；头没有眼睛（头在小区域里分辨率不够） |
| v7 | 头排除（新分区 + 三角形重排） | 头原版、装备盖住身体；花纹斜、不对称 |
| v8 | 全部映射左右镜像 | 用户确认端正对称，好看（男、女） |

- 不要先猜成因：每一步都用用户的截图和客户端里读到的实际文件核对（我曾多次发现"用户装的版本"和我以为的不同）。
- 不要对着 Python 的 heredoc 写含反斜杠的路径，脚本一律用文件写入；中文路径多的批处理脚本用 Write 写文件，不要内联。

## 同一天的关联教训（头盔挂点，Codex 的 HELMKT1A，用户通过）

- 库尔男性戴 T7 头盔飘在头顶偏前：原因是模型里头盔挂点（id 11）的 pos 与它所在骨的 pivot 不一致（多出前 0.166、高 0.21）；把 pos 恢复为 pivot 后用户确认通过（只改一个模型的 12 个字节）。详见 [port-coa-race-appearance-wxl](../port-coa-race-appearance-wxl/SKILL.md)。
- **我的误判（记下来）**：我只在 YB/YJ/XA 里搜，没找到库尔男的这件头盔变体，就写"缺 KTM 变体"，还说"男性仍用 Hu 前缀"。Codex 核对后纠正：原生 KTM 在 Patch-6，且种族前缀是男女共用的。**说"缺资源/没有某文件"之前必须扫全所有档案**（包括基础补丁和 Patch-6），并说明哪些档案没扫到。
- 但"挂点 pos 与骨 pivot 不一致"这个怀疑是对的（这是我从两个模型的挂点数据里发现的），Codex 用它修好了。

## 未解决/边界

- 靴子、披风、长袍、袖子需要新几何体，本方法不能解决。
- 想要没穿装备时身体与原版完全一样，只能退回 v3 的"相加混合"（装备显得发光）；二者是取舍。
- 与别人对同一 M2 的改动（如背盾 helper）冲突：先对齐，在对方新模型上重新生成这一层即可（脚本可重复运行）。
- 底图分辨率受合成大小限制，鳞片细节会比原版糊。
