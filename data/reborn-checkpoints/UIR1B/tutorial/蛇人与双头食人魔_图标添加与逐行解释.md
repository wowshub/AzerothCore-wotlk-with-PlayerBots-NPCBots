# 蛇人与双头食人魔：圆形图标怎么加上去（UIR1B）

这次加的是角色创建页上的两个**预览入口**：联盟蛇人在黑铁矮人左侧，部落双头食人魔在赞达拉巨魔右侧。两个入口同一行、同尺寸、向外对称排列。它们尚不是可以正式创建的新种族。

你可以把它想成三层：**头像照片 → 阵营圆相框 → 鼠标/选中的发光圈**。Lua 决定放在哪里、点了做什么；XML 决定按钮沿用什么样式；BLP 保存头像像素。

本文按实际冻结文件编写。原文件指已安装的 UIR1A，新文件指你截图中的 UIR1B；另附没有预览入口之前的 CharacterCreate.xml，避免把两个“旧版本”混为一谈。讲解逐行覆盖本次所有新增、替换、删除的 Lua 代码和 XML 节点，未修改的大量原有创建页代码保留完整源码供对照。

## 2. 为什么 XML 和 Lua 都要有

CharacterCreate.xml 第 3 行加载 CharacterCreate.lua，第 4 行加载 RebornRacePreview.lua。后者是 A 阶段已加上的：

```xml
<Script file="CharacterCreate.lua"/>
<Script file="RebornRacePreview.lua"/>
```

第一行让旧创建页逻辑先准备好。第二行让新增预览脚本接在后面。`file` 是同一 GlueXML 目录下的文件名，`/>` 表示节点结束。如果只把 Lua 放进 MPQ 而没有加载它，客户端不会仅凭文件存在就运行它。

本次 B 在 XML 最后的 `</Ui>` 前加两行，原来这里没有这两个按钮：

**新 XML 第 2483 行**

```xml
<CheckButton name="RebornSethrakPreviewButton" inherits="CharCreateRaceButtonTemplate" parent="CharacterCreate" hidden="true"/>
```

`CheckButton` 是可以显示选中状态的按钮；`name` 给它唯一名字，让 Lua 能找到；`inherits="CharCreateRaceButtonTemplate"` 沿用现有种族头像、圆环、名字、高亮样式；`parent="CharacterCreate"` 表示挂到角色创建页；`hidden="true"` 表示先隐藏，等 Lua 摆好后再显示。这行是蛇人入口。

**新 XML 第 2484 行**

```xml
<CheckButton name="RebornOgrePreviewButton" inherits="CharCreateRaceButtonTemplate" parent="CharacterCreate" hidden="true"/>
```

`CheckButton` 是可以显示选中状态的按钮；`name` 给它唯一名字，让 Lua 能找到；`inherits="CharCreateRaceButtonTemplate"` 沿用现有种族头像、圆环、名字、高亮样式；`parent="CharacterCreate"` 表示挂到角色创建页；`hidden="true"` 表示先隐藏，等 Lua 摆好后再显示。这行是双头食人魔入口。

模板定义在本文件 `CharCreateIconButtonTemplate`（约第 291 行）和 `CharCreateRaceButtonTemplate`（约第 369 行）。前者定义 62×62 按钮、borderfaction 外圈、HighlightTexture 鼠标亮圈和 CheckedTexture 选中亮圈；后者继续继承它，补上种族按钮行为。我们随后用 Lua 替换点击回调，否则沿用原生选种族行为会错误地进入未完成的数据链。

外圈可以比按钮本身大：模板外圈大小 121×122，使用素材自身透明留白及原有定位；不要看到这个数字就改成 62。高亮纹理使用现有图集 UI-CharacterCreatePatchwerk_nuevo 的相应 UV 区域。本次没有修改共享图集，旧种族格子保持原状。

## 5. 对称位置怎么计算

旧创建页中，黑铁矮人布局按钮 23 位于左侧，赞达拉布局按钮 25 位于右侧。当前顶栏参考值是中心左右 185，邻居间距 70。新增蛇人从黑铁中心再向左 70，食人魔从赞达拉中心再向右 70，形成对称外扩。代码直接跟随邻居，而不是把屏幕坐标写死：

```text
蛇人 ←70→ 黑铁矮人 … 中间 … 赞达拉巨魔 ←70→ 双头食人魔
```

`i==1 and -70 or 70` 大白话就是“第一个用 -70，否则用 +70”。此项目黑铁对应真实 raceID 26、赞达拉对应 raceID 18；布局按钮序号 23/25 不能拿去写种族数据库。

`entries` 中 `key="Sethrak"` / `key="Ogre"` 用来拼资源目录；title 用来写阵营与名字。模型路径的 `prefix="Reborn\\Preview\\UIR1A\\"` 继续保留，因为 B 没搬模型。顶部残留 UIR1A 注释、未再使用的 launcher 局部变量不代表装错版本，窗标题 UIR1B 才是本次改过的标记。

## 6. 头像如何从方形变圆形

CoA 来源是种族资源包中的 `Interface/Icons/CoA_Race_Sethrak.blp` 与 `CoA_Race_Ogre.blp`。A 已复制到各自 `Reborn/Preview/UIR1A/.../icon.blp`，B 从已安装且哈希一致的 A 图标取输入。

不是把方形头像上盖一个圆环就算裁圆。圆环中间和四角仍可能透明，下面方形头像会漏出来。实际做法是保持每个像素的 B/G/R 颜色不变，只把圆以外的 Alpha（透明度）降为 0，边缘用一像素过渡。不同缩略层 mip 都处理，避免缩小时方角重新出现。

以下是实际 build.py 中的原代码，逐物理行解释。它只支持本次确认过的 **BLP2、encoding=3、原始 BGRA**；不能拿去盲处理 DXT 压缩 BLP。

**build.py 第 17 行**

```python
for race,mpq in [('Sethrak','Patch-YB.mpq'),('Ogre','Patch-YC.mpq')]:
```

循环两个种族以及各自来源 MPQ，蛇人归 YB，食人魔归 YC。

**build.py 第 18 行**

```python
 data=bytearray((B/'backup_原文件'/mpq/f'Reborn/Preview/UIR1A/{race}/icon.blp').read_bytes());assert data[:4]==b'BLP2' and data[8]==3
```

读取已备份的 A 图标为可修改字节数组；检查前四字节是 BLP2、头部第 8 偏移处编码为 3，否则直接报错，防止改坏其他格式。

**build.py 第 19 行**

```python
 w,h=struct.unpack_from('<II',data,12)
```

从文件偏移 12 读取两个小端无符号 32 位数：原图宽、高。<II 是 struct 的格式描述。

**build.py 第 20 行**

```python
 for level in range(16):
```

最多检查 16 个缩略图层；level 从 0 开始，0 是完整尺寸。

**build.py 第 21 行**

```python
  off=struct.unpack_from('<I',data,20+4*level)[0];size=struct.unpack_from('<I',data,84+4*level)[0]
```

从偏移表 20+4×level 读取该层起点 off，从长度表 84+4×level 读取字节数 size。

**build.py 第 22 行**

```python
  if not off or not size:continue
```

层不存在或长度为 0 就跳过。continue 的意思是继续下一层。

**build.py 第 23 行**

```python
  mw,mh=max(1,w>>level),max(1,h>>level);assert size>=mw*mh*4
```

右移 level 位相当于尺寸连续除以 2，最小留 1 像素；确认该层至少能容纳宽×高×4 字节。

**build.py 第 24 行**

```python
  for y in range(mh):
```

按行遍历这一层每个像素。

**build.py 第 25 行**

```python
   for x in range(mw):
```

每一行内再逐列遍历像素。

**build.py 第 26 行**

```python
    dist=((x+.5-mw/2)**2+(y+.5-mh/2)**2)**.5;coverage=max(0,min(1,min(mw,mh)*.455-dist+.5));at=off+4*(y*mw+x)+3;data[at]=round(data[at]*coverage)
```

同一行四句：dist 算像素中心到图片中心距离；coverage 用半径 min(宽,高)×0.455 算覆盖率并夹到 0—1，+0.5 做柔边；at 定位 BGRA 四字节的第 4 个 Alpha；将旧 Alpha 乘覆盖率并四舍五入。RGB 三字节完全不动。

**build.py 第 27 行**

```python

```

选择输出 MPQ 导入目录和 UIR1B 私有文件名；创建父文件夹；写入新图标。没有直接写运行 MPQ。

## 7. 点一下为什么发光，为什么还不能创建

XML 继承选中纹理，Lua 的 `SetChecked(true)` 才点亮它；只设置圆头像并不会自动变成选中。顶栏点击调用 `Open(index)` 打开预览，关闭面板时新增两行 `SetChecked(false)` 清除亮环。

原有防护仍在：Open 把 active 设为 true；CreateCharacter 包装函数发现 active 就提示“预览尚未开放创建”并 return；返回创建页把 active 清掉，原本的正式种族创建逻辑才恢复。这不是创建数据已经完成，也不证明种族掩码/出生地已打通。

面板内的小头像换用了圆形 BLP，但仍保留旧方形选中贴图。因此第二张截图里，面板蛇人小头像周围出现方形高亮，与上排已完成的圆形选中圈是两个不同控件。本次没有暗中扩大修改范围。

## 8. 怎样安装与回滚

此 B 包是 A 后的四文件增量，不是完整客户端。已安装并截图测试的用户无需再导入。新测试环境先准备本项目匹配基线与 UIR1A，再将 B 的“导入PATCH-YB”三个文件按内部路径导入 YB，将“导入PATCH-YC”一个文件导入 YC。保存并关闭 MPQ 编辑器后启动游戏。共享 CharacterCreate XML/Lua 以 YB 中唯一累计版本为准，不能让别的补丁用同路径旧文件盖掉。

回滚前先比较当前目标文件与本次输出 SHA256：如果不同，可能别人已继续更新，先合并，不能直接整包回退。如果仍相同，可恢复 B 的 backup_原文件 中两个 A 界面文件；新增圆图在确认无其他引用后才移除，A 原方图与模型仍保留。不要覆盖整份 YB/YC，也不要动 YA。
