# WD135A 灵魂链接雕像 — 累计候选测试包

承接已验收WD134A+B，保留两项“无限距离”修正。本批仅新增一个完整主动技能：灵魂链接雕像 / Spirit Link Idol，节点13133，技能9003953，生物900232。它有生命守恒、雕像替换和正式方案依赖，作为独立测试批次。

## 效果与获得

- 50级酿造方案，先有魔精波动4733（其前置洛阿祝福4715），免费点选13133并保存，0 AE/0 TE。
- 瞬发，自身附近放置，3%基础法力、3分钟冷却、1秒公共冷却；持续14秒，每2秒均衡10码内存活团队玩家的生命百分比。
- 按最大生命加权分配当前生命，保持总生命严格不变，每名存活目标至少1点生命。整数取整可有微小百分比差异，不是所有人得到相同血量。
- 不产生治疗或伤害事件，不暴击、不受治疗加成放大、不触发吸血、水晶护盾或治疗复制。死者不参与，也不复活。
- 真人和PlayerBot（玩家类型）可参与；普通宠物、NPCBot和无关玩家不参与，与上游玩家筛选一致。需同相位、范围和视线。
- 与旧灵魂/宁静等雕像共用一个Idol槽，成功放置才替换旧雕像；独立于守卫、巫毒大锅和宠物。死亡、换图、退出、切方案失去技能时停止。敌人可以攻击雕像。
- 复用已安装灵魂神像900192的外观映射（当前1101122），不是新增CoA专属链接粒子；官方节点图标同时提供给插件与MPQ。

## 覆盖步骤（已有WD134B）

1. 备份源码、客户端Patch-XA.mpq/Interface、服务端DBC和Characters/World数据库。
2. `01_覆盖到源代码根目录`覆盖工程，由你编译、部署服务端。新增`RebornWitchDoctorSpiritLink135.inc`及`RebornWitchDoctorLinkBalance.h`必须一起覆盖。
3. `02_覆盖到客户端根目录`覆盖客户端；将`client_mpq输入_导入现有Patch-XA`内容按内部相对路径导入现用Patch-XA.mpq。MPQ备份放在Data外。
4. 停服，将`03_覆盖到服务端根目录`覆盖服务端；客户端与服务端DBC分别提供，禁止互换。
5. Characters库只执行`server_SQL/01_CHARACTERS_WD135A_必须执行.sql`；World库只新增执行`server_SQL/13_WORLD_WD135A_必须执行.sql`。World要求旧灵魂神像900192已安装，缺依赖或ID冲突会拒绝，不强行覆盖。
6. 重启客户端和服务端，在正式酿造方案点选并保存。不要递归运行累计历史SQL。

包内源码不含昨天两项语言/观察者文件；它们已独立推送d1d508eca/33fc9762f，应保留工程现有版本。本包不会覆盖它们。没有生成worldserver.exe，也没有替你部署或执行生产SQL。

## 测试顺序

1. 50级、已保存洛阿祝福和魔精波动，点选雕像保存；检查0点消耗、技能书/拖动图标、重登和切方案。49级、缺前置、其他专精不能点选。
2. 两名同队玩家在雕像10码内，一人满血一人半血、停止其他治疗/伤害：下一次2秒脉冲应使双方生命百分比接近一致，总生命不变。不同最大生命再测一次。
3. 示例：A为10000/10000，B为2000/20000，分配后约4000/10000与8000/20000。请用生命数值核对；这是血量重新分配，治疗统计未增加是正常的。
4. 移出10码、离队、死亡或视线阻挡的角色不参与。单人施放不增加生命；不应把低血量玩家分配到0血。
5. 检查14秒结束、3分钟冷却和3%基础法力。先放旧雕像再放链接雕像，反向也测；每次只剩一个雕像，守卫及巫毒大锅不消失。
6. 施法者死亡、退出、跨地图、切掉酿造方案，以及敌人打掉雕像后，均不再分配生命。回归WD134两技能及其射程显示。

## 检查与回滚

188项隔离MySQL检查、29组双端数据/Lua检查（含旧84药水数值场景及实际117位M.Save）、两个实际C++单元MSVC /Zs通过。实际分配头文件编译测试10000组随机总量守恒/上下限及确定性例子通过。旧DBC行和字符串池不变，新增一技能/图标/技能书条目，WD134B射程保留。现有雕像模型在实际MPQ中已读到。
这些离线检查不等于实机通过；范围、视线、外观、多人和生命周期由上述步骤验证。

`rollback_WD134B`保存本次修改的旧版文件。回退时恢复双端对应DBC、旧源码并重新编译。若已保存新节点，旧schema不能读取新位，必须配合恢复测试前Characters备份，不能只回退源码或手动删点数。
