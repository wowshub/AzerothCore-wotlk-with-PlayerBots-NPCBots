# WDN6B：清本期间 NPCBot 跟随坦克（第 2 步候选）

本包仅实现跟随目标接入；游戏测试：**未运行**。不是巫医最终累计总包。

## 安装

基于当前已安装 WDN6A 和 WDN5I 的累计源码。将 `01_覆盖到源代码根目录` 内的 src、modules 合并覆盖源码根目录，然后由用户重编核心与模块、部署重启。修改 bot_ai.h 会影响依赖它的 NPCBot 编译单元，请确保依赖重编；新增文件仅为头文件，无需新增 cpp 构建项。
只有 5 个源码文件；没有 02 客户端、03 数据，没有 SQL，无需导入数据库。本包没有服务器 EXE。没有部署、push、release。勿用本包覆盖更晚的共享文件；来源哈希见验证记录/inputs.json。

## 实现与生命周期

- bot_ai.h/cpp：新增 GetFollowAnchor 与启动期注册的解析回调；master、拥有者 GUID、装备和职责归属均不修改。清本模式根据有效运行状态即时计算，不储存每个 NPC 的目标裸指针。
- DcNpcFollowBridge.h、mod_dungeon_clear_loader.cpp：模块启动注册只读桥接，使用 FindRunOwner 和已有 PartyTank；不另选坦克，不给真人发送移动命令。
- _calculatePos、CheckBotCast、SetBotCommandState、GlobalUpdate：日常站位目标改用有效坦克，间距和队形槽仍用主人配置。自由 NPCBot 保留原距离逻辑。
- botmgr.cpp：有效坦克跟随期间，抑制同图因离主人太远产生的旧召回；其他地图/限制召回保留。

|场景|目标与恢复|
|---|---|
|副本内，清本启用且未暂停，同组同图同相位有效 PartyTank|跟随坦克|
|停止/结束/暂停、无有效运行者|解析恢复主人|
|坦克死亡/离线/离队/换图/相位不符|恢复主人；原复活逻辑继续|
|更换有效 PartyTank|随已有 PartyTank 更新切换|
|主人换图/离线、NPC退组或离开副本|恢复原主人跟随/原生命周期处理|
|待命、停止、禁用、解绑|保留显式指令，不强行移动|

恢复目标不等于立刻打断动作：下一次原生允许的移动更新才走位。保留 HasPriorityHealingTarget、读条、引导和休息保护；不承诺战斗中强制贴坦克。坐骑同步仍用主人，未新增坦克坐骑同步。副坦不另选，跟随清本 PartyTank。

## 交接中的调查结论

1. 真人坦克：当前 DungeonClearPartyTankValue / DcLeaderSignal 只接受具备 PlayerbotAI 且清本有效的坦克；纯手动真人不能直接成为当前 PartyTank。本批没有硬改选举。最小后续改动是将“人工坦克锚点”与“自动清本移动驱动/运行归属”分开，调整选举和停止生命周期，绝不能接管真人移动。托管角色是否满足现有选举条件仍需游戏验证。
2. 紫罗兰监狱：怪物脚本 AttackStart/MoveInLineOfSight 可由事件敌人主动触发，不调用清本开怪就绪检查，因此被动迎战可能发生在等待队员期间。不能据此认定当次事故就是这一原因；未获得该次完整日志关联。有限检查 Playerbots.log 尾部 4000 行未找到 stranded-recovery，不能当成从未执行的证据。真人集合等待逻辑未改；跟坦克减少 NPC 因主人落后而落后，但不能解决所有卡路、战斗和施法阻塞。
3. 失联恢复：DcStrandedRecovery 遍历 Player 组员，要求 PlayerbotAI，显式跳过 IsRealPlayer；NPC Creature 不在其中。当前 IsRealPlayer 在 master==bot 时为真，因此 selfbot 被这条路径排除；用户观察到的传送需另查运行版本或其他传送来源。
4. 建议 WDN6C 单独接入 NPC 失联恢复：复用同一无进展计时、坦克和距离阈值，限制存活、同图同相位、非战斗且未禁用，并检查落点。**本包未实现传送到坦克**，避免跟随与传送同时改变而难以定位测试问题。
