# DCBAR1A 批次验收：清本记录多选/对比、输出量与首领战统计、常用组加 NPC 机器人、顶栏首领数（Claude）

- 日期：2026-10-25。
- 用户原话：「前面开发的列出的几个更新 都通过了  可以一步一步地推送了」；「推送好我们开始下一步的开发」。这句话回应的是助手当天给出的待测清单；用户没有逐项复述，所以按那份清单整体登记为“用户确认通过”。更早的单项原话：「测试右键的比较 和删除 都可以了 不错测试已通过」（DCRUN2A 右键对比统计与批量删除）。另有用户截图显示 DCSTAT3A 的输出、承伤、治疗三列已出数据。
- 范围：
  - **DCRUN2A**（插件 3.6-reborn108）：副本记录 Ctrl/Shift 多选、批量删除、对比统计窗口；筛选（副本/结果/难度）与底部汇总；各副本最快全清星标；服务器重启后“进行中”显示为“已中断”；明细本地缓存。
  - **DCSTAT3A**（插件 3.6-reborn109 + 服务端 DcPlayerRuns.cpp、TestRun/DcDeathLog.cpp/.h）：每个队员的输出量、输出目标、按首领战的用时/总伤害/DPS/各人占比、每人承伤；统计窗口上方数字不再落后于明细，窗口开着时随一局的进行状态自动刷新。
  - **DCGRP1A**（插件 3.6-reborn110）：邀请列表里的 NPC 机器人可拖入常用组、多选、右键加入；“组队”不邀请 NPC 机器人。
  - **DCBAR1A**（插件 3.6-reborn111）：清本顶栏“首领 x/y”只数真首领（魔枢 1/4），目标/事件另列。
- **不在范围 / 未测边界**：
  - NPC 机器人的承伤暂不记录（队伍表里显示“-”）；承伤仍是整局合计，没按首领战拆开；
  - “组队”不会召回 NPC 机器人（需要确认用哪条 NPCBot 召回命令）；
  - 服务器重启前打的局没有输出量数据；
  - 顶栏加上“目标 x/y”后在不同宽度下是否挤到右侧按钮，未逐一核对。
- 链条核对：服务端三个文件与 DCSTAT3A 包的 backup_原文件哈希（CRLF 归一）一致；插件四个文件依次 DCRUN2A → DCSTAT3A → DCGRP1A → DCBAR1A，每个包的 backup 与上一个包的最终文件一致，起点是插件仓库 d738880（3.6-reborn107）。服务端 cl /Zs 0 错误 0 警告；插件用 Lua 5.1 语法检查。
- 插件仓库 wowshub/mod-dungeon-clear-addon：四个提交 3a7c870、0a684a8、2133a8d、9b07c21，tag v3.6-reborn108…v3.6-reborn111。

## 部署顺序（用户执行）
1. 服务端：覆盖三个文件后编译（不需要 CMake Generate，没有 SQL）。
2. 客户端：用插件仓库的 v3.6-reborn111（或 Release 附件）覆盖 `Interface/AddOns/DungeonClear`，`/reload`。
